# File Edit SOP

## 触发场景

- 修改、新增、删除项目文件。
- 用户要求实现功能、修 bug、更新文档。
- 需要处理可能已有的用户改动。

## 必须流程

```text
1. 改前读取目标文件
2. 明确最小改动范围
3. 使用 apply_patch 或项目内文件工具做局部修改
4. 不碰无关文件
5. 改后运行最小必要验证
6. 总结改了什么和验证结果
```

## 禁止事项

- 不读取文件就直接改。
- 覆盖用户未授权改动。
- 做无关重构。
- 用破坏性 git 命令回滚别人的改动。
- 文档中加入不必要的日期时间。

## 用户改动处理

- 工作区可能是脏的，默认认为已有改动属于用户。
- 如果用户改动与任务无关，忽略。
- 如果用户改动影响当前任务，基于现状继续做。
- 只有改动互相冲突且无法安全处理时才问用户。

## 验收标准

- 单文件小改：至少确认文件内容和相关语法。
- Go 改动：优先 `go test ./...` 或相关包测试。
- JS 插件改动：`node --check`。
- 文档路径变更：`rg` 检查旧路径是否残留。
